# Mission prioritaire pour Work — catalogue intégral, avant les prix

Ouvrir le dossier de ce ZIP avec Node.js >=20 dans un environnement pouvant joindre `api.tcgdex.net`. Ne pas traiter 20 000 URL du JSON d'images comme si elles constituaient les fiches du catalogue. Le catalogue (cartes, extensions et détails) doit être téléchargé depuis TCGdex FR et EN, fusionné par **ID exact** (FR en priorité, EN pour les IDs absents en FR).

1. Lancer `npm run check`. Vérifier que les tests (dont le builder avec petites données locales) passent.
2. Lancer `npm run pack:catalog -- --index inputs/pokevault-index-visuels.json --strict --output dist`. Cela fait une première collecte intégrale du catalogue et de **chaque fiche détaillée** ; laisser le processus continuer même plusieurs heures. Les requêtes sont modérées et le cache `.catalogue-cache` permet la reprise après interruption avec la même commande, sans `--refresh`.
3. Inspecter `dist/assets/offline/catalogue-report.json`, `detailsComplete: true`, `cardDetailsAvailable == uniqueCardIds`, `cardDetailsErrors: []` et `setDetailsErrors: []`. Résoudre tout problème, relancer, et refuser de livrer une sortie partielle. Vérifier aussi `orphanCards` ; les cartes sans extension correspondante doivent être examinées, et ne peuvent pas être ignorées.
4. La sortie `dist/` embarque **l'intégralité des données de catalogue** et les fiches dans 32 fragments chargés à la demande. L'index `verified-index.json` reprend les URL du JSON fourni. Il ne contient **pas** les illustrations elles-mêmes ; un second build de scans sous licence/autorisation valide sera nécessaire pour garantir des illustrations sans réseau.
5. Tester la version `dist/` derrière un serveur HTTP, couper tout accès réseau externe dans un navigateur neuf et vérifier le catalogue global, les extensions, la recherche et l'ouverture de fiches (puis les gros scrolls). Ne pas conclure au succès hors ligne sur la seule base de tests unitaires. Sur PWA, vérifier l'installation du service worker et que tous les fragments de fiches sont mis en cache, compte tenu des quotas navigateur. Dans un conteneur natif, tous les fragments sont déjà physiquement inclus dans `dist/`.
6. Sauvegarder et préserver la collection : **ne pas toucher à `localStorage.pv_collection`**. Publier sur la même origine HTTPS pour que la collection existante soit retrouvée.
7. Les cotes viendront **après**. Le fichier `ROADMAP-COTES.md` décrit : une passe initiale globale, puis seulement deux boutons explicites de mise à jour (catalogue entier / cartes possédées). Ne pas déclencher de scan massif au démarrage.

Ne pas publier un paquet de milliers de scans de cartes sur un dépôt public sans vérifier les droits de redistribution. Créer une branche et une PR pour le code seulement.
